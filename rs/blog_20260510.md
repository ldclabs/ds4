# 400M Tokens Later: My Agent Used DeepSeek 4 to Build a Rust DeepSeek 4 Inference Engine

Some AI coding demos generate a todo app in 30 seconds.

This was not that.

I gave Anda Bot a `/goal`: study the C inference engine for DeepSeek V4 Flash, written by antirez, and port it to Rust under `rs/`. The Rust version should migrate the tests, pass them, run the real model, and get as close as possible to the C CPU reference path.

Three days later, the result was `ds4.rs`: 11,748 lines of Rust, a CPU inference engine that can load the real 81 GB GGUF model and generate text on a Linux server.

The surprising part: the code was written by DeepSeek 4 Pro through Anda Bot. My role was to set the goal, provide real hardware test results, correct direction when needed, and occasionally stop the agent before it tried to melt my laptop with an 81 GB model file.

## Credit First: This Builds on antirez's Work

The most important credit comes first.

`ds4.rs` did not come out of nowhere. It builds on antirez's `ds4` project. antirez, the creator of Redis, wrote a C inference engine for DeepSeek V4 Flash and made the implementation, model format, runtime path, and engineering details available for study.

What we did here was learn from that work: read the C implementation, align with its model format and tokenizer behavior, and then attempt a Rust rewrite of the CPU inference path.

So this is not a story about reinventing `ds4`. It is a thank-you to antirez for publishing a fascinating, complex system, and an experiment in whether an AI agent can absorb and extend a serious systems project.

## The Goal I Gave the Agent

The original goal was simple to state and hard to satisfy:

> /goal Study this C inference engine carefully. Use it as the reference implementation. Rewrite it in Rust under `rs/`. Migrate the C unit tests to Rust, make them pass, and produce a working Rust version of `ds4.rs` with performance comparable to the C implementation.

That task touches almost every layer of an inference runtime: binary model parsing, mmap, GGUF metadata, the fixed DeepSeek V4 Flash architecture, JoyAI tokenization, KV cache, MoE routing, low-bit quantized matrix multiplication, SIMD intrinsics, Rayon parallelism, CLI behavior, test-model generation, and C/Rust numerical alignment.

In other words, it is a great stress test for a long-running coding agent. The goal is clear, the path is messy, failures are guaranteed, and the final answer must run on a real model.

## What It Built

The final `ds4/rs` directory is a pure Rust CPU inference engine. It does not depend on Metal or CUDA, and it uses the same GGUF model files as the C engine.

The main pieces are:

- `gguf.rs`: mmap-based GGUF reading, metadata parsing, tensor parsing
- `tokenizer.rs`: JoyAI / GPT-2 byte encoding tokenizer, BPE, special tokens
- `quant.rs`: Q2_K, Q4_K, IQ2_XXS, Q8_K, Q8_0 dequantization and dot products
- `forward.rs`: full forward pass with attention, MoE FFN, Sinkhorn, and KV cache
- `session.rs`: autoregressive generation state
- `src/bin/ds4.rs`: production CLI with one-shot and interactive chat modes
- `gen_test_gguf.rs`: tiny synthetic GGUF generation for local tests

The Rust codebase is 11,748 lines. The test suite includes 158 `#[test]` entries. With a tiny generated GGUF model, 98 library tests and 60 integration tests pass.

## The Most Dramatic Bug Was Hardware

The biggest interruption was not a model bug. It was my hardware.

The DeepSeek V4 Flash q2 GGUF model is around 81 GB. My development machine could not safely load it. Early in the project, Anda Bot tried to touch the real GGUF file twice and froze my computer.

Eventually I rented a 64 vCPU, 256 GiB RAM AMD server on Alibaba Cloud. The workflow became: Anda Bot writes code locally and pushes branches; I pull on the server, build with `cargo build --release`, run the real model, and paste the logs back. The agent then continues from the evidence.

That taught an important lesson for agents: just because a tool can access a file does not mean it should read it. Just because a command can run does not mean the machine can survive it. Resource constraints need to be first-class state in long-running agent systems.

## From Garbage Output to Real Generation

When the real model first ran, it did not work immediately.

First came `missing vocabulary size`. The root cause was that the GGUF metadata used the `deepseek4.*` prefix, while the Rust parser only looked for `ds4.*` and `llama.*`.

Then came output like `ĠæĢ³...`. That had two causes: the output path was not reversing GPT-2 byte encoding, and the prompt template treated special tokens such as `<｜User｜>`, `<｜Assistant｜>`, and `<think>` as ordinary text to pass through BPE.

After fixing the tokenizer and special-token prompt construction, the model finally generated readable text.

Then came the harder correctness and performance bugs:

- An early SIMD version made prefill stall.
- The P1-P5 optimization branch produced repeated `aplaplapla...` output.
- Q2_K SIMD had a horizontal-sum bug.
- IQ2_XXS SIMD had a signedness bug.
- Speculative decoding had 0% token acceptance on the real DS4 model.

None of these were fixed by simply asking the model to try again. They required branch isolation, trace flags, C/Rust numerical comparisons, and real server feedback.

## Performance

On the 64 vCPU, 256 GiB RAM AMD Linux server, Rust v0.2.0 reached:

| Metric                        | Rust v0.2.0 | C CPU reference |
| ----------------------------- | ----------: | --------------: |
| Greedy decode, 81 GB q2 model |  ~1.1 tok/s |      ~2.7 tok/s |

This does not mean the Rust engine beats antirez's C engine overall. The C engine's main path is macOS Metal GPU, while `ds4.rs` is currently CPU-only, CLI-only, with no disk KV cache and no server mode.

The more accurate statement is: on the CPU reference path, an agent-written Rust version can run the real 81 GB model, while decode speed is still behind the C CPU reference.

That is already wild.

## What This Says About Anda Bot

This experiment reinforced my belief that the future of AI programming is not just code snippet generation. It is letting an agent work inside a real repository for a long time.

A useful coding agent needs to remember the goal, understand the codebase, recover from failure, know when to run tests, know when to branch, know when to revert, and know when to say: this optimization looks clever, but the real model rejects it.

Anda Bot's `/goal` mode survived a multi-day systems programming task. It also exposed areas that need to become stronger: resource constraints, automatic continuation, staged acceptance gates, and a better protocol for remote hardware feedback.

But the result is enough to make me excited: an agent, using DeepSeek 4 Pro, wrote a real Rust inference engine in a few days.

Not a slide deck about AI agents. Not a toy demo. 11,748 lines of Rust in a real repository.
